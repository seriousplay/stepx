# 客户端更新

StepX Companion 每次启动在后台读取一次 [GitHub 最新正式版](https://github.com/xydzf520/stepx/releases/latest)。不需要 GitHub 账号，也不依赖手机连接；不会在使用过程中反复轮询。

1. 发布了适合当前系统的新版本时，底部版本号左侧出现 **检测到新版本**。简洁模式也有同一入口。
2. 点击查看版本和更新说明，再点 **下载更新**。显示实际下载量、速度和进度，可取消或收起继续工作。
3. 下载后校验包大小、SHA-256、文件路径和包结构。校验通过后显示 **安装并重启**，点击才会退出当前程序。
4. 安装器保留完整旧目录，新版本启动并确认成功后完成更新；启动失败则恢复旧目录并重新打开旧版本。备份位于原安装目录旁 `.backup-*`，不会自动删除个人文件。

也可在 **设置 → 关于 → 软件更新** 手动检查。当前版本比 GitHub 公开版高时会明确提示，不降级安装。手机系统 OTA 仍在小工具中，和此功能互不影响。

## 发布包约定

- 来源固定为 `xydzf520/stepx` 的 GitHub Releases，不接受第三方镜像或任意下载链接。
- 正式标签 `vX.Y.Z`，排除草稿和预发布。
- `StepX-Companion-X.Y.Z-linux-x86_64.tar.gz`
- `StepX-Companion-X.Y.Z-windows-x86_64.zip`
- `StepX-Companion-X.Y.Z-macos-arm64.zip` / `macos-x86_64.zip`
- 使用 GitHub asset 的 SHA-256 digest；旧发布缺少 digest 时，必须提供同名 `.sha256` 文件。
- 发布工作区使用 `scripts/package-release.py`（当前位于 `releases/stepx-public/`）生成完整包：可执行程序、运行时、ADB 等工具、资源与脚本一起更新，不能只上传一个 exe。打包版本必须与 Cargo.toml 一致。

包摘要防止下载损坏，信任基础是这个 GitHub 仓库及 HTTPS；不是独立签名服务。当前支持用户可写的便携目录及可写的 macOS app 安装位置。只读目录、磁盘映像和 App Translocation 位置会停止安装并说明原因，不自动提权。macOS 会验证现有包签名，更新不移除系统隔离属性。

## 安装与数据

下载、解压、安装准备均在后台；UI 仅读取进度事件。进度条使用有限时长的绘制动画，遵守设置中的“减少动态效果”。收起后不会持续绘制面板。

启动更新前检查正在运行的任务、文件迁移、未保存设置、对话草稿和附件；请先完成或保存这些内容。配置和文件库保存在安装目录之外；旧目录也整体保留。安装辅助程序使用独立的 Python 运行时，避免 Windows 的运行中文件锁阻止替换。

测试覆盖真实 GitHub 发布包下载/摘要、恶意路径与链接、截断下载、取消、实际进程启动确认、启动失败回滚，以及原生窗口底部入口与更新面板。跨平台最终验收应在相应系统执行；Linux 结果不能替代 macOS/Windows 实机结果。
