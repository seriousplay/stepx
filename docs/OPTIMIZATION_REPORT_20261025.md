## 1. 总体架构概览

StepX Companion 采用「跨平台原生桌面客户端 + Android 伴侣应用 + 受控特权桥接」三层协同架构，在不解锁 Bootloader、不刷写启动分区、不破坏用户账号数据的前提下，打通桌面端与 StepX 手机之间的 AI 协同、文件归档、设备控制与系统级服务维护。

```
┌───────────────────────────────────────────────────────────────────────────┐
│                        Desktop Client (Rust + facloud_ui)                 │
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────────┐  │
│  │ Amoo 统一工作台│ │ 存储扩容/文件 │ │ 短信/通话/推送│ │ 小工具与Google诊断│  │
│  └──────┬───────┘ └──────┬───────┘ └──────┬───────┘ └────────┬─────────┘  │
│         └────────────────┴────────────────┴──────────────────┘            │
│                                  │                                        │
│            USB ADB / Wireless ADB (mDNS GUID + 动态端口重连)               │
└──────────────────────────────────┼────────────────────────────────────────┘
                                   ▼
┌───────────────────────────────────────────────────────────────────────────┐
│                     StepX Phone (Android 16 / 172 固件)                    │
│  ┌─────────────────────────┐  ┌────────────────────────────────────────┐  │
│  │ StepX伴侣 (APK)          │  │ 特权与自愈组件 (DEX / Boot / Pairing)   │  │
│  │ · AutoConnectService    │  │ · CompanionRuntime / CompanionGrant    │  │
│  │ · AmooConnectionService │  │ · GoogleLoginRuntime (153 项权限/登录)  │  │
│  │ · 扩容文件库与相册预览    │  │ · PairingDaemon (UID 2000 签名校验桥接) │  │
│  └─────────────────────────┘  └────────────────────────────────────────┘  │
└───────────────────────────────────────────────────────────────────────────┘
```

### 核心设计准则
1. **真实回执驱动**：所有涉及手机端修改、文件迁移、模型执行、权限修复的操作，均以手机端实际回读与 SHA-256 校验为准，绝不把“请求已发出”当成“执行已完成”。
2. **无损与可回滚**：系统级维护（Google 服务适配、输入法切换、开机恢复组件）在执行前保存快照与回执，支持一键撤销，不清除用户账号与应用数据。
3. **最小权限与身份核验**：每次设备操作前核对硬件序列号（`ro.serialno`），配对守护进程与特权 Provider 严格校验 `StepX伴侣` 签名与调用方 UID。

## 2. 界面视觉与交互体验全面优化（UI & Interaction）

### 2.1 视觉规范与布局收敛
- **一屏一件事**：主导航精简收敛，移除冗余装饰、阴影与营销词汇；依靠 4px 倍数间距令牌（`S1`–`S6`）、三级字重（Normal / Medium / Semibold）与语义色圆点表达状态。
- **固定状态栏与非侵入式加载**：连接状态、加载进度、发送等待动效及 GitHub Star 入口固定于底部状态栏（28px），刷新时不插入顶部横幅，彻底消除页面跳动。
- **跨平台窗口与简洁模式（Compact Mode）**：
  - 支持全局/窗口快捷键唤起简洁对话窗（Windows / Linux 默认 `Ctrl + Alt + A`，macOS 默认 `Command + Option + A`），支持冲突检测与恢复默认。
  - 完整窗口与简洁模式共享当前会话、草稿与待发送附件，模式切换零阻塞。
  - 针对短窗口与多附件场景自适应分配编辑区、附件区与留白高度，确保发送按钮始终可见。

### 2.2 统一草稿与行内确认机制
- **选择不等于执行**：设置修改、存储扩容规则配置、目录选择先生成本地草稿，底部固定显示未保存状态与「保存 / 放弃」入口，跨页或退出前提醒未保存变更。
- **行内二次确认**：对背屏写入、文件上传/删除、原件恢复、应用卸载、短信发送、电话拨打、Studio 推送/同步及系统工具操作统一采用行内确认条，明确列出目标设备、操作范围与后果。
- **停止操作零阻碍**：停止生成任务、停止语音朗读、停止背屏播放保持即时响应，不设确认弹窗阻碍。
- **操作提醒审计**：记录本次运行最近 30 条确认提交与回执完成事件（不记录敏感密钥），区分“已提交”与“已完成”。

### 2.3 编辑器、键盘路由与无障碍细节
- **独立光标与选区交互**：输入框光标独立绘制不挤动文字；对话正文与输入框均支持鼠标拖拽选区、快捷键复制/剪切/粘贴/全选及右键上下文菜单。
- **键盘事件统一分发**：修复完整窗口与简洁模式下主键盘及小键盘 `Enter` 路由，保留 `Shift + Enter` 换行与中文输入法（IME）候选词组合保护。
- **本机语音朗读（TTS）**：消息回复提供本机语音朗读与停止控制，当手机侧官方音频接口未返回有效音频时不展示虚假播放态。
- **平滑滚动与动效控制**：全局滚轮加入短距离缓动，历史阅读或选中文本时不被新消息强制拉到底部；严格遵循「减少动态效果」开关。

## 3. Amoo 统一工作空间（Amoo Workspace）

### 3.1 Chat-First 默认对话与按需工作流
- **单一主入口**：将原本分散的 Amoo 对话、Amoo Work 桌面协作与 Studio 本地应用创作整合为统一的 **Amoo** 入口，共用一个任务流与输入框。
- **默认对话，按需切换**：文字提问、上传图片识图、附加文档问答默认均走轻量「对话」模式，不再自动弹出复杂工作进度卡。
- **显式创作模式**：点击输入框内模式菜单可按需选择「处理文件」「生成图片」「制作应用」；提交前展示计划确认卡（核对输入资料、模型来源与保存目录），确认后仅对当次请求生效，随后自动恢复为「对话」模式。

### 3.2 多模态交付与自动化校验
- **桌面文件处理（Excel / Word / PPT / Markdown）**：
  - 手机 Amoo 模型生成结构化桌面操作计划，由电脑端在受限工作目录内执行。
  - Excel 成果在窗口内直接渲染缓存计算值与表格预览，保留原文件公式；执行器复用重复写入成功回执，并对无效格式提供最多两次自动纠偏。
- **真实图片生成**：等待手机端实际图片附件生成并拉取至本地、校验文件头与字节大小后才标记完成，支持简洁模式内直接预览原图与另存为。
- **手机模型驱动的应用创作与 28 项真机级验收**：
  - 未配置自有大模型 API 时，可直接复用已连接手机的 Amoo 模型与账号生成完整 Web 应用源码；已配置自有 API 时独立计费并在确认卡标明来源。
  - 电脑端在隔离无头浏览器中自动执行 28 项交互与 DOM 断言检查，失败时保留已生成文件并按错误反馈驱动模型修复，通过后方可一键发送至手机作品库或同步至 Studio 官网草稿。

## 4. 通信、文件互传、存储扩容与背屏矩阵

### 4.1 通信中心（短信 / 通话 / 手机推送 / IM）
- **短信与电话**：发送短信与拨号前完成号码格式与 SIM 卡状态预检，通过统一确认单展示收件人、SIM 卡槽、正文与短信分段数；取消操作完整保留草稿。
- **通知镜像与 IM 协同**：后台同步忽略未变化的会话与通知快照以降低 CPU 与 ADB 开销，读取失败采用指数退避重试；支持在桌面查看手机通知并明确提示“在手机打开”或“同步清除”。

### 4.2 文件管理与可靠互传
- **桌面级浏览体验**：支持可点击的逐级面包屑路径导航、双击进入目录或取回电脑打开、右键菜单（打开、下载、复制路径、重命名、移入回收站）。
- **端到端完整性校验**：文件发送至手机（`StepX伴侣 → 文件 → 接收文件`）与从手机拉取均核对文件字节大小与 SHA-256 摘要，过期临时预览副本按 7 天策略自动清理。

### 4.3 存储扩容（三步向导 + 九步无损归档）
- **三步配置向导**：
  1. **选择文件范围与保留期**：覆盖 `DCIM` 根目录与 `DCIM/Camera` 照片/视频，以及 `Documents`/`Download` 常用文档；明确「保留最近 7 天 / 30 天」仅迁移更早文件，「写入完成后迁移」需文件静置满 2 分钟。
  2. **选择电脑保存目录**：固定显示 `StepX Storage` 归档路径，防止误选临时目录。
  3. **只读清单预览与确认开启**：展示可迁移文件数、总大小、保留期内文件数与最早迁移时间，确认并经手机端回读成功后才启用自动迁移。
- **九步原子迁移与相册联动**：
  - 依次执行：`手机原件 SHA-256 → 传输至电脑临时文件 → 电脑端 SHA-256 校验 → 正式落盘与回执记录 → 手机端二次复核 → 生成系统相册带标记预览图 → 写入 .stepxlink 占位 → 经授权 ADB 通道彻底清理原件（防系统回收站残留） → 手机端确认完成`。
  - 手机用户在系统相册查看预览图时，可通过「分享 → 取回电脑原图」在线拉回原文件并校验打开；已恢复回手机的文件自动标记排除，避免重复迁移。

### 4.4 背屏矩阵控制（17×23 Pixel Matrix）
- **精准硬件映射**：针对 StepX 背屏 17×23（391 字节）LED 矩阵自动剔除四个圆角不可见像素（12 个角点掩码），支持 1–8 级亮度缩放与反色控制。
- **预设图案与自定义媒体**：内置「赛博闪电」「猫咪眨眼」「咖啡时刻」「律动音符」像素动效，支持本地图片与 GIF 动图采样预览，应用前展示参数摘要并支持一键停止恢复。

## 5. 同 Wi-Fi 自动重连与开机自愈稳定性

### 5.1 手机与桌面双向同网自动连接
- **手机端 `AutoConnectService`**：首次配对成功后开启同局域网监听；自动连接配置存储于 Android **Device Protected Storage（设备保护存储）**，手机重启后在首次解锁并完成权限自愈后自动恢复连接，同时严格尊重用户手动暂停状态。
- **桌面端无线 GUID 与动态端口追踪**：
  - 自动解析并记住已授权手机的无线 ADB GUID，兼容 mDNS 广播中带 `(2)` 等冲突后缀的设备名。
  - 当路由器重分配 IP 或 Android 无线调试端口变化时，后台自动重发现并无缝切换传输通道。
  - 在线检测独立于前台操作队列，连续两次探测失败才判定断开，短暂网络抖动或 USB/无线切换期间完整保留当前 Amoo 会话、草稿与附件。

### 5.2 开机恢复与权限自愈守护（`companion-boot`）
- **陈旧回执识别**：权限回执严格绑定系统 `boot_id`、`system_server` PID 与伴侣/GMS 组件版本，杜绝系统服务重启后旧回执误报“已就绪”。
- **互斥执行与 20 秒稳定性校验**：开机恢复组件采用文件锁互斥执行，完成背屏、无线配对、后台冻结豁免与熄屏唤醒租约授权后，额外执行 20 秒 `system_server` 进程稳定性观察；若发生原生层异常则停止自动重试并保留现场供回滚。

## 6. Google 服务四层能力与认证边界矩阵

| 层级 | 能力模块 | 当前状态 | 技术实现与真机验证边界 |
| :--- | :--- | :--- | :--- |
| **L1** | **基础框架与商店组件**<br>（GSF / GMS / Play 商店） | **已就绪** | 检测系统预装与 `mtg16` 适配组件状态（GSF 36、GMS 26.41.31、Play 53.6.15），Google Play 商店应用浏览、下载与更新均正常可用。 |
| **L2** | **运行时权限与自愈守护**<br>（153 项权限 + 重启/更新自愈） | **153/153 已守护** | `StepX伴侣` 与特权桥接监听开机解锁及 GMS / Play 商店包覆盖更新事件，后台延迟合并并串行恢复全套 153 项运行时与签名级权限，无需重新插拔 USB。 |
| **L3** | **通用账号凭据与应用链接**<br>（Credential Manager + App Links） | **通用登录正常** | 校验 Google 官方签名后登记 `GoogleIdService` 凭据提供者回退，并接入官方域名验证接收器（App Links 代理），保留其他密码管理器与默认链接偏好。**Google Play、Gmail、Chrome、Gemini 原生对话**均可正常登录并稳定使用。 |
| **L4** | **硬件级密钥证明边界**<br>（Key Attestation / Play Integrity 强校验） | **出厂硬件根边界** | StepX 工程机出厂四级硬件证书链（`Android Keystore Key → Stepx Android Attestation ECC Leaf → Stepx ECC Intermediate CA → Stepx Root CA`）非 Google 官方认证信任根。针对强制校验硬件证明链的接口（如 **X 原生 Google 一键登录**在服务端 `GenerateAttestationTokenV2` 返回 `214 Validation Failed` 且 `VerifyAndroidAttestationKeysMutation` 拒绝私钥证明），在 Bootloader 锁定、AVB Green、无内核模块（无 `CAP_SYS_MODULE` / Magisk / KernelSU / Zygisk）环境下无法伪造硬件根证书。建议在 X 内使用**「账号密码 + 通行密钥（Passkey）」**或**官方网页版**登录。 |

## 7. 公开仓库脱敏同步与跨平台发布工程

为确保内部研发仓库向公开开源仓库（`releases/stepx-public`）同步时零敏感信息泄露、许可证与依赖路径合规，新增了自动化脱敏同步工具 `scripts/sync-public-repo.py`：

1. **严格白名单同步**：仅同步经审计的源码目录（`desktop/src`、`desktop/tests`、`desktop/assets`、`desktop/android-bridge`、`desktop/amoo-background`、`desktop/companion-app/{src,res,tests,third_party,libs}`、`desktop/companion-permissions`、`desktop/neo-agent-adapter`）、顶层构建描述文件以及公开脚本与文档，自动排除本机私有诊断快照（`diagnostics/`、`backups/`）与内部设备评估手记。
2. **许可证与 Vendor 依赖重写**：自动将公开版 `desktop/Cargo.toml` 的 `license` 重写为 `"AGPL-3.0-only"`，并将 `facloud_ui` 与 `markdown_parser` 路径重写为 `"../vendor/..."`。
3. **宿主路径与设备序列号脱敏**：自动将构建与验证脚本中的开发机本地 JDK / Android SDK 路径及测试机序列号重写为标准环境变量（`JAVA_HOME`、`ANDROID_HOME`、`STEPX_ADB`、`STEPX_SERIAL`）。
4. **密钥模式强制阻断扫描**：对所有待同步内容及 `releases/stepx-public` 全量文本文件扫描 `ghp_`、`sk-`、`PRIVATE KEY` 等敏感凭据模式，支持 `--check` 干跑预检模式，一旦命中任何密钥特征立即以非零状态码阻断发布。
