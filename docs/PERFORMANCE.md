# 性能与响应性验证

验证版本：StepX Companion 0.2.0，Linux 本地构建 `261023174449`。

## 这次修复

- 背屏预览的横向布局曾把无限宽度传给点击区域索引，导致主线程卡在 R-tree 插入。现在预览区域有明确尺寸，索引也拒绝非有限坐标。
- 每个 17×23 点阵由一个绘制元素处理，灯珠不再分别创建布局节点和点击区域；整个图案仍可被父级预设卡片选中。
- 背屏默认不生成帧、不扫描图库。进入后启用预览，离开或最小化后暂停，返回时延续进度并保留手动暂停选择。最小化状态检测使用 Linux / Windows 的本地窗口状态；macOS 本轮未实测。
- 图库扫描进入后台线程，只在打开图片页或主动刷新时启动；静态预设缩略图只生成一次。
- 未进入扫码流程时不生成二维码。空闲轮询由每秒 10 次改为每秒 2 次；连接检测保留。进度动画限制为每秒 4 次，倒计时按秒刷新。
- Amoo / Work 的 Markdown 解析按内容缓存，最多 64 条、原文总量 2 MiB，单条超过 256 KiB 不进入缓存。非活动页面不启动额外的附件预览下载。
- 投屏窗口位置查询和停止进程等待移到后台；关闭侧栏只释放该窗口的渲染资源，避免重置其他窗口正在使用的 GPU 实例。

用户主动开始的传输、生成、应用背屏和任务执行仍会继续接收结果；退出页面不会取消手机上已应用的效果。

## 实际检查

| 检查 | 结果 |
| --- | --- |
| 原先黑屏的背屏页面 | 调试版从启动到截图约 4.5 秒，原故障复现时超过 40 秒仍无响应 |
| 12 个页面连续切换 4 轮 | 48 次通过；包含首页、背屏、Amoo、Work、文件、应用、短信、电话、工具、连接、账号、关于 |
| 主线程定时心跳 | 最大间隔 500 ms，与空闲调度周期一致 |
| 非活动背屏 | 断言验证预览停止、时间不再推进 |
| 最小化与恢复 | 原生窗口最小化后预览停止、时间冻结；恢复后继续播放，断言通过 |
| 切页内存观察 | 预热后约 266–269 MiB（调试版），后续轮次未持续增长 |
| 正式版首页 | 手机已连接；8 秒采样 CPU 约单核 0.25%，RSS 约 230 MiB |
| 界面单元测试 | 42 项通过，包括非法坐标回归、预览生命周期、缓存上限和已有交互逻辑 |
| 投屏 | 窗口跟随、按钮作用和开关测试见 [投屏验证](MIRROR_VERIFICATION.md) |

以上为当前 Linux 机器上的测量，不代表所有电脑上的性能保证。框架独立测试目标存在原有测试依赖/测试 API 缺失，本轮未通过编译；相关非法坐标回归已在桌面客户端测试目标中执行并通过。

## 复测

```sh
cargo test --manifest-path desktop/Cargo.toml --features ui-capture --bin stepx-companion
cargo run --manifest-path desktop/Cargo.toml --features ui-capture -- --demo --verify-ui-performance
cargo run --manifest-path desktop/Cargo.toml --features ui-capture -- --demo --verify-ui-minimize
```

后两条只使用示例数据，分别执行切页和最小化生命周期断言，完成后输出 `UI_PERFORMANCE` / `UI_MINIMIZE` 并退出。最小化用例适用于 Linux / Windows。实际发行包未启用这些测试入口。
