# Studio × StepX Companion

v0.2.3。**使用自己的模型，在电脑生成和验证作品，再保存到手机或 Studio 官网。**

## 从需求到可用作品

1. **设置模型**：进入 Studio → 设置，选择 OpenAI Chat Completions 或 Anthropic Messages 协议，填写 API Base URL、模型名和密钥。保存后测试真实调用，也可读取服务返回的模型目录。
2. **描述需求**：在工作台输入用途、交互和验收要求。当前支持单文件 HTML 离线工具与小游戏，例如待办、记账、计算器和触控游戏。
3. **运行与修复**：模型生成页面与验收步骤，工作台用真实浏览器执行点击、输入、刷新、文字与本地存储检查，并检查 JavaScript 错误和手机宽度溢出。失败报告交回模型修复，最多三轮；可以随时停止。
4. **查看成果**：每轮代码、截图、报告独立保存。只有通过检查且源码校验一致的成果可交付；可继续描述修改要求。
5. **在手机使用**：一键保存到 StepX伴侣，核对文件 SHA-256，再打开作品。作品文件和各自的本地数据保留在手机，断开电脑仍可使用。
6. **同步官网**：选择官网实际返回的构建模型，保存为新的 Studio 应用草稿并回读核对源码。点击继续编辑可直接进入项目。同步不等于公开发布或通过官方真机测试。

本地验证需要已安装的 Chrome / Edge（也支持 Chromium）。单个作品上限 2 MB，手机最多保留 40 个离线作品；可以在手机作品库移除。首批不支持多文件工程、联网服务、任意终端命令或手机系统接口。手机界面的真实体验仍应由用户验收，自动检查通过不代表全部需求已被穷尽验证。

## 模型与账号

| 能力 | 使用的账号 | 模型选择 |
| --- | --- | --- |
| 本地工作台生成、修复 | 用户自己配置的 API 服务 | 自填模型或服务返回的目录；真实调用核对权限 |
| 官网继续编辑、官方构建 | 手机伴侣内的 Studio 官网账号 | 官网实际返回的构建模型目录 |
| Amoo / Amoo Work | 手机 Amoo 账号 | 沿用手机支持的模型与 Token 权益 |

官网没有向本项目开放可直接复用的裸模型推理接口，因此本地工作台不会把 Studio 构建接口冒充本地模型，也不会默认消耗手机的 Amoo Token。自己的模型按服务商规则计费。支持兼容协议不代表每个服务的套餐都开放全部模型；列表展示与推理权限分别验证。

API 密钥保存在本机用户配置目录的 `stepx-companion/studio-lab/model.json`；Unix 文件权限为 0600。它不进入作品源码、日志、手机或官网。更换 API 服务地址时不会自动沿用旧服务密钥。API 地址要求 HTTPS，本机 localhost 可使用 HTTP。此版采用本机私有配置文件存储，不声称已经接入系统钥匙串。

## 官网免重复登录

首次请在手机伴侣的官方页面使用与 Amoo 相同的账号完成登录，再点击“完成登录”。伴侣更新后会话继续保留。原厂不允许伴侣直接用 Amoo 原生凭据换取官网身份，因此首次官方验证仍需用户完成。

之后桌面“继续编辑”通过伴侣自己的官网会话打开独立 Chrome / Edge 窗口：

- 会话只传入本应用创建的临时浏览器，不读取默认浏览器或其他 App 的账号。
- 核对当前官网账号、项目归属及编辑页地址后才报告成功。
- 同一项目重用已打开标签，保留正在编辑的内容；不同项目分别打开。
- 断开官网、切换账号或退出应用时清理桌面临时会话；不会删除官网项目。

会话传递使用应用内部管道，没有对外调试端口，不把 Cookie 写入命令行、日志或作品。浏览器仍可能受到官网的会话到期与重新验证策略影响；失效时回到手机官方登录页处理。

## 自动作品同步

| 目录 | 内容 | 下一步 |
| --- | --- | --- |
| 官网项目 | 当前官网登录账号的应用、技能、智能体，包含草稿 | 继续编辑、关联同编号手机测试版本 |
| 手机可用 | Amoo 原生授权的“我的作品” | 打开体验；技能 / 智能体由 Amoo 确认安装 |
| 我的收藏 | 主动保存的项目和体验入口 | 分享二维码、手机桌面入口 |
| 本地成果 | 自己的模型生成并验证的离线作品 | 预览、继续修改、手机保存、同步官网 |

进入 Studio 自动同步，页面可见时每分钟刷新，离开停止轮询。同步前后核对账号；失效或切换后不把旧目录当新账号结果。官网与手机原生目录独立显示，一方失败不抹去另一方结果。编辑链接不作为公共体验二维码分享。

云端源码同步只创建新应用，手机记录本伴侣创建的项目；源码写入还要核对账号、项目归属和创建记录，不覆盖已有官网作品。空项目会补固定的最小网页构建配置；有模板则保留模板文件。同步会回读源码并保存官网版本检查点，回执返回该版本。官方审核、真机测试和发布仍受官网流程约束，不自动代替用户公开发布。

“官网测试包已构建”仅表示官方生成了测试安装包，不表示手机运行已通过。2026-10-23 的验收中，官网成功构建了测试 APK，但该测试容器优先加载云端预览，遇到 `CORE_PREVIEW_SANDBOX_NOT_READY`；此路径仍需在官网继续处理预览环境。已验证可用的交付路径是保存到伴侣的离线作品库，不依赖该云预览。详见 [Studio 验证记录](STUDIO_VERIFICATION.md)。

## 运行隔离

生成的代码只在独立浏览器运行，不与已登录的 Studio 窗口共用会话。验证时禁止外部请求；手机作品使用独立 origin、独立本地存储，禁止网络、外部导航、本地文件访问和原生 JavaScript 桥。上传分片、完整性校验和打开回执分别验证；成功保存、页面载入与功能验收不是同一状态。

## 维护与验证

主要模块：`studio_lab.rs` 与 `studio-lab-runtime.py` 负责模型和运行验证，`studio_delivery.rs` 负责交付与官网源码同步，`studio_browser.rs` 负责隔离编辑窗口，Android `StudioLocal` / `StudioLocalActivity` 负责手机离线运行，`StudioWeb` 负责范围受限的官方会话与请求。

自动化检查覆盖协议与密钥保存、源文件与报告一致性、真实浏览器交互、失败条件、停止、账号作用域、源码路径和手机打开回执。可用 `verify_studio_lab`、`verify_studio_delivery`、`verify_studio_editor` 示例，在已配置服务及明确授权的手机上复验；真实账号与设备诊断不提交公开仓库。

本次主要实测环境为 Linux 和 PZ261A。Windows / macOS 的浏览器路径与运行逻辑已实现，尚未完成对应实体平台的验收。官网接口可能变动，错误会保留在界面供重试，不伪报成功。
