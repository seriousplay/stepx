# Studio × StepX Companion

2026-10-23 网站与真机接口核对。定位：**电脑创作，手机体验，作品随身，方便分享**。

## 官方平台与伴侣各自负责什么

Step Studio（https://studio.stepx.com/）已有应用、智能体、技能三种构建器，提供 AI 对话创作、项目文件、模型选择、连接器、模板与组件、预览、真机测试、发布和体验二维码。应用构建器可以创建 APP 或网页游戏。不能把这些能力重复做成一组空按钮。

Companion 负责跨设备最后一公里：保存项目入口、把实际体验链接送到已连接手机、回读确认保存、在手机打开、请求创建桌面图标、导出分享二维码，以及直接打开 Amoo 的“我的作品”。官网仍负责生成、审查、云构建、发布和账号权限。

| 用户需求 | 本次实现 | 条件与真实边界 |
| --- | --- | --- |
| 开始创作 | 应用、智能体、技能三个可修改的需求起点，复制需求并打开官网 | 用户在官网选择构建器并发送；不会擅自消耗生成额度 |
| 继续编辑 | 保存真实构建器地址，直接打开官网项目 | 使用默认浏览器自己的登录态 |
| 免扫码上机 | 自动同步手机账号作品后直接打开；也支持手工收藏链接 | 手机已授权 ADB、安装新版 StepX伴侣；手机回执成功才显示已保存 |
| 断开电脑使用 | 手机“任务 → Studio 作品”持久作品库 | 网页作品仍需网络，体验链接失效后需要更新 |
| 桌面入口 | Android ShortcutManager 正式固定快捷方式 | 系统可能需要手机确认；仅请求成功不等于已添加，可回读核对 |
| 分享 | 二维码预览、保存 PNG、复制分享文案；手机系统分享 | 只对官方体验链接生成二维码，不把私有编辑地址包装成公共作品 |
| 技能 / 智能体上机 | 一键打开官方 Amoo 我的作品，显示分步骤引导 | 需要同一账号、官网真机测试就绪，再在手机确认安装 |
| 新手登录 | 官方入口、浏览器会话复用、同账号说明 | 连接 ADB 不等于网站登录，不能伪造登录成功 |

## 手机账号自动同步（0.2.1 真机验证）

伴侣通过 Android AccountManager 的系统账号选择器申请自身的 `basic` 授权。手机确认后，伴侣在手机内请求官方 Amoo 我的作品接口，同步应用、技能、智能体三类目录；账号令牌不导出到电脑，不放进 URL 或日志。进入 Studio 自动同步，此页每分钟刷新，离开页面不轮询。支持断开同步、重新连接、账号切换校验与官方体验链接直接上机。

已验证三个目录 HTTP 200、官方 code 0，当前账号实际返回应用 1、智能体 0、技能 1；连续刷新、断开后拒绝读取、重新授权同账号均通过。同步得到的应用已在真机浏览器打开。网页项目页有更多未提交测试的草稿，所以本目录明确标为 Amoo 我的作品，不能称为官网全量项目。

## 网页登录的边界

公开网站脚本使用官方账号 SDK，StepX 域名对应 `login-studio.stepx.com`，可见短信验证码与密码登录流程。核对的公开 SDK 与页面没有提供“已连接手机 Amoo → Studio 网页会话”的正式交换入口。

网页登录仍复用默认浏览器自己的会话。真机实测：伴侣获授权的手机凭据访问 Studio 两个 identity 接口均返回 401；原厂 `weblogin` 授权明确返回“不支持该包的登录请求”。没有绕过包名、签名或登录权限检查。此版本不承诺插线就能登录网页，也不会导出浏览器 Cookie。

真正的插线免密登录需要平台支持 OAuth / device authorization：电脑生成一次性挑战 → 手机显示目标设备与请求范围 → 用户确认 → 官方服务签发限定用途、短时有效的授权码 → 浏览器建立 Studio 会话。ADB、root 或 Android 系统权限本身不能替代该服务端能力。

## 为什么不能把链接直接当成技能

原实现写死了三个不存在的示例应用地址；忽略文件推送、广播和打开错误，并提前显示“已部署”。还会在进入 Studio 时自动转发网关端口、展示派生 Token。

本次移除了整段伪部署与自动网关开放链路。保存链接只称为保存作品入口；技能与智能体遵循官方真机测试和手机安装流程。普通网页不能因为保存在伴侣中就获得相机、背屏、文件或 GUI Agent 系统权限。

## 实现

- `desktop/src/studio.rs`：官方域名 / 路由校验、本机原子持久化、链接去重、二维码、显式设备身份校验、手机保存回执。
- `desktop/src/ui/studio_state.rs`、`desktop/src/ui/pages/studio.rs`：手机账号作品 / 收藏与分享 / 开始创作 / 连接与上机四页；所有文件和 ADB 操作在后台任务中执行。
- `StudioProvider`：仅 ADB shell 或自身 UID 可调用，且受 DUMP 权限保护，无新增网络监听端口。
- `StudioStore`：手机应用私有存储，原子写入，最多 200 条；再次发送同一 URL 更新而不重复堆积。
- `StudioActivity`：独立手机作品库、浏览器打开、系统分享、正式桌面快捷方式；关闭电脑不影响已保存入口。
- 未新增 Android 权限；不自动安装网页提供的 APK，不自动发布到云端。

支持的链接：`https://studio-api.stepx.com/t/<id>`、`https://studio.stepx.com/builder/{app|agent|plugin}/p_<id>`、`https://studio.stepx.com/preview/p_<id>`。后两种只能继续编辑 / 查看，分享与手机保存要求第一种。认证参数、陌生域名、非 HTTPS、任意 intent 及带用户凭据的 URL 均拒绝。

## 后续值得与平台合作的方向

1. **全量官网项目与免密登录**：手机账号作品已打通；完整云项目、草稿和网站会话仍需官方 OAuth 授权范围与接口稳定承诺。
2. **构建回执**：网页真机测试后通过官方回调或扩展返回结果，减少一次复制；回调需要一次性随机数、源校验和明确用户动作。
3. **手机能力组件**：基于官方端侧 MCP 支持情况提供背屏、GUI、文件组件。需要按权限显示能力，给用户预览与停止入口，不能默认复用 Amoo 全部模型权限。
4. **Amoo Work → Studio**：把已确认的需求与产物交给构建器，可先使用需求复制与显式文件上传；不在用户不知情时自动上传工作文件。
5. **发布与分发**：官方发布链接与临时体验链接分开，增加到期检测、版本更新与回退。在公开 API 未保证前，不承诺自动续签。
